# 国际化规范（I18N）

## 1. 本文档目的与适用范围

本文档定义 EndfieldMap 多语言 (i18n) 的目录结构、命名空间约定、加载策略、类型生成流程、在 React 与 service 中的使用方式，以及 fallback / 语种检测 / SW 更新提示一致性的约束。

适用于：

- `packages/map-service/src/locales/**`（locale JSON 文件）；
- `packages/map-service/src/service/i18n.ts`（i18n 服务）；
- `packages/map-service/src/@types/resources.d.ts`（类型生成产物）；
- 所有调用 `useTranslation` / `i18nService.translate` 的业务代码。

---

## 2. 文件结构

### 2.1 路径模式

```
packages/map-service/src/locales/<locale>/<namespace>.json
packages/map-service/src/locales/bundled.ts
```

- **locale** 目录名采用 BCP-47 形式（区域大写、连字符）；
- **namespace** 一个文件 = 一个 namespace，JSON 顶层是平坦的 key-value（嵌套 key 用 `.` 分隔写在键名里，i18next 自动解析）；
- **`bundled.ts`** 是聚合导出，**不是** locale，不要往里放新语种。

### 2.2 当前 14 个 locale

| Locale | 语种 |
| --- | --- |
| `de-DE` | 德语（德国） |
| `en-US` | 英语（美国） |
| `es-MX` | 西班牙语（墨西哥） |
| `fr-FR` | 法语（法国） |
| `id-ID` | 印尼语 |
| `it-IT` | 意大利语 |
| `ja-JP` | 日语 |
| `ko-KR` | 韩语 |
| `pt-BR` | 葡萄牙语（巴西） |
| `ru-RU` | 俄语 |
| `th-TH` | 泰语 |
| `vi-VN` | 越南语 |
| `zh-CN` | 简体中文（默认 / fallback） |
| `zh-TW` | 繁体中文 |

新增语种需所有 namespace 同步建文件，缺失 namespace 会让 `tsc --noEmit` 失败（类型生成会校验完整性）。

### 2.3 当前 8 个 namespace

| Namespace | 用途 |
| --- | --- |
| `common` | 通用：按钮文案、提示、占位符（`defaultNS`） |
| `agreement` | 用户协议 / 隐私条款 |
| `error` | 错误码对应文案（业务错误 / 网络错误） |
| `header` | 顶部导航 / 应用头 |
| `lang` | 语种名（zh-CN 在各语种下的本地化显示） |
| `popup` | 弹层 / 浮层文案 |
| `settings` | 设置页 |
| `sidebar` | 侧边栏 |

新增 namespace 标准：

- 当某业务模块的 key 超过 30 条且与现有 namespace 主题不重合 → 拆新 namespace；
- 拆新 namespace 后必须在所有 14 个 locale 下创建对应 JSON（即便仅有英文也要建空 `{}`）。

## 3. 添加 / 修改文案的流程

### 3.1 标准流程

```bash
# 1. 编辑某个 namespace JSON
$EDITOR packages/map-service/src/locales/zh-CN/common.json
$EDITOR packages/map-service/src/locales/en-US/common.json
# ... 其它 12 个 locale 同步

# 2. 重新生成类型
pnpm lng:type

# 3. 类型检查
pnpm -w tsc --noEmit
```

### 3.2 类型生成产物

`pnpm lng:type` 写入：

```
packages/map-service/src/@types/resources.d.ts
```

它把所有 namespace 的 key 联合作为 `Resources` 接口暴露给 `react-i18next` 模块声明合并，从而让 `t('common:save')` 这种调用具备字面量类型补全与"key 不存在"错误。

### 3.3 硬要求

- **改完 JSON 必须跑 `pnpm lng:type`**，否则 `tsc --noEmit` 失败（CI 阻断合入）；
- 不要手动编辑 `resources.d.ts`；
- 不要把 key 写成 `t('common.save')` 这种点号形式（项目 namespace 分隔符是 `:`），否则类型推断会失效。

## 4. 在 React 里使用

### 4.1 标准用法

```tsx
import { useTranslation } from 'react-i18next';

export const SaveButton = () => {
  const { t } = useTranslation('common'); // 默认 namespace
  return <button>{t('save', { defaultValue: '保存' })}</button>;
};
```

```tsx
const { t } = useTranslation(['common', 'error']);
// t('save', { ns: 'common', defaultValue: '保存' })
// t('save_failed', { ns: 'error', defaultValue: '保存失败' })
```

### 4.2 defaultValue 强约束

**所有 `t(...)` 调用必须带 `defaultValue`，且 `defaultValue` 一律使用中文兜底**。原因：

- 即便 i18n 加载失败或 key 缺失，用户仍能看到合理文案；
- 在开发期可以快速发现"我忘了去 JSON 里加这个 key"——因为类型层会先提示，而界面层会显示中文兜底。

✅ 推荐：

```ts
t('save', { defaultValue: '保存' });
```

❌ 反例：

```ts
t('save'); // 无 defaultValue, 缺失时显示 'save' 裸 key
```

### 4.3 切换语种

`react-i18next` 自身 `i18n.changeLanguage(locale)`，但项目层面统一封装在 `MapService.i18nConfig` / `i18nService` —— UI 改语种走 `i18nService.changeLanguage(locale)`，由它同时更新 RxDB 偏好、`<html lang>`、ServerService 的 `Lang` header。

## 5. 在服务 / 非 React 代码里使用

```ts
import { mapService } from '@/services';

const text = mapService.i18nService.translate('save_failed', {
  ns: 'error',
  defaultValue: '保存失败',
});

// 带插值
const text2 = mapService.i18nService.translate('welcome', {
  ns: 'common',
  defaultValue: '欢迎 {{name}}',
  name: user.nickname,
});
```

- service 层错误文案统一用 `error` namespace；
- 业务子类 Error 在抛出时即翻译为当前语种文案，UI 直接显示 `err.message`，避免 UI 层再做一次 t()。

## 6. 命名规范

### 6.1 namespace 选择

| 场景 | namespace |
| --- | --- |
| 通用按钮、提示词、表单占位 | `common` |
| 错误码 / 错误提示 | `error` |
| 设置页字段、开关说明 | `settings` |
| 弹层标题 / 内容 | `popup` |
| 顶部 / 侧边栏 | `header` / `sidebar` |
| 协议、隐私文本 | `agreement` |
| 语种本地化名 | `lang` |

不确定归属 → 默认 `common`；后续可批量迁移。

### 6.2 key 命名

- **snake_case**（`save_failed`、`confirm_delete`、`network_error`）；
- 按业务模块分子树：`marked.create_failed`、`marked.delete_confirm`、`guide.step_intro`；
- 不要把同义文案重复定义 → 比如 "确认" 在不同位置统一用 `common:confirm`，不要 `common:ok` + `popup:confirm` + `settings:apply` 三份。

## 7. 插值与复数

### 7.1 插值

i18next 占位符语法 `{{var}}`：

```json
{ "welcome": "欢迎 {{name}}" }
```

```ts
t('welcome', { name: '指挥官', defaultValue: '欢迎 {{name}}' });
```

- 变量名英文 snake_case；
- defaultValue 也要带占位符，否则 fallback 路径会丢值。

### 7.2 复数

**当前项目未启用 ICU 复数 / i18next 复数插件**。如需复数（例如 "{{count}} item / items"），分两步走：

1. 提案：在 issue 内说明哪些 key 需要复数，统计影响面；
2. 实施：启用 i18next 自带 `plurals` 形式 key（`xxx_one` / `xxx_other`），并升级类型生成脚本以识别复数后缀。

短期内不要私自引入 ICU；如需"一个 / 多个" 差异表达，临时通过 `count > 1 ? t('items') : t('item')` 处理。

## 8. fallback 与语种检测

### 8.1 配置

参考 `packages/map-service/src/service/i18n.ts`：

| 项 | 值 |
| --- | --- |
| `defaultNS` | `common` |
| `fallbackLng` | `zh-CN` |
| `detection` 优先级 | `i18next-browser-languagedetector` 默认（querystring → cookie → localStorage → navigator → htmlTag） |

### 8.2 加载策略

- `apps/web/src/services/index.ts` 用 `import.meta.glob('../../../../packages/map-service/src/locales/**/*.json')`（lazy 函数形式），返回 `Record<path, () => Promise<{ default }>>`；
- 传入 `MapService` 的 `i18nConfig.resourceLoader`，按需读取 `<locale>/<ns>.json`；
- 因此**不会**一次性把 14×8=112 个 JSON 全部塞进首屏 bundle，按 locale + ns 动态加载。

### 8.3 fallback 行为

- 当前语种缺失 key → 回退到 `zh-CN` 同 namespace 同 key；
- `zh-CN` 也缺失 → 使用 `t(...)` 的 `defaultValue`（中文兜底）；
- `defaultValue` 也未提供 → 显示裸 key（开发期才允许）。

## 9. SW 更新提示语种一致性

已知问题：Service Worker 的"有新版本，是否刷新"提示文案在某些路径下自己读 `navigator.language`，导致提示语种 != 用户在应用内选的语种（详见 `PERF-AUDIT.md`）。

### 9.1 规范层约束

- **SW 更新提示文案必须复用 `i18nService.currentLocale`**，不要再独立检测 `navigator.language`；
- 提示文案的 key 进入 `common` namespace（例：`common:sw_update_available`、`common:sw_update_now`、`common:sw_update_later`）；
- 文案获取方式：SW 通信回主线程后，调 `mapService.i18nService.translate('sw_update_available', { ns: 'common', defaultValue: '检测到新版本' })`。

不要在 SW worker 里直接 `t(...)`（worker 内没有 i18next 实例）—— 由主线程拉取翻译后通过 `postMessage` 注入。

## 10. 反例集

| 反例 | 问题 | 推荐 |
| --- | --- | --- |
| `t('save')` 无 defaultValue | i18n 加载失败时显示 `save` 裸 key | `t('save', { defaultValue: '保存' })` |
| 改 JSON 后没跑 `pnpm lng:type` | `tsc --noEmit` 失败 | 改完即跑 |
| 新增 namespace 仅在 zh-CN 建文件 | 其他 locale 类型生成报错 | 14 个 locale 同步建（空 `{}` 也可） |
| 用 `t('common.save')` 点号分隔 | 项目 namespace 分隔符是 `:` | `t('save', { ns: 'common' })` |
| 错误文案散落各处 | i18n 维护成本高 | 统一 `error` namespace + service 层翻译 |
| 在 worker 里直接 `i18next.t` | worker 没有 i18next 实例 | 主线程翻译后 postMessage |
| SW 提示自读 `navigator.language` | 与应用内语种不一致 | 复用 `i18nService.currentLocale` |
| 私自启用 ICU 复数库 | 类型生成 / 类型联合崩塌 | 走 RFC，统一升级 |
| key 命名 camelCase / 混杂 | 风格不一致 | 一律 snake_case |
| `defaultValue` 写英文 | 用户兜底体验差 | 一律中文兜底 |
| 业务自己手动加 `Lang` header | 与 ServerService 重复 | `ServerService` 自动注入 |
